# FIX13 built: fixes from the independent review of S13, S02 and S05

Branch `fix13` (from the main branch with the Beast Pen and bonding days, S14 and S15). The review looked at S13 (the Beast Handler as a read-only app, with a first meeting the Bastion rolls), S02 (the "Changes from the Explorer" list and notices in Management) and S05 (Bastion Events removed). Twelve defects were confirmed; all twelve are fixed or covered by tests. Nothing was pushed.

## What changed, in the order of the review's list

1. **The reveal now lands on the subspecies the Bastion holds now** (`tools/beasthandler/model.js` `M.revealTarget`, `tools/beasthandler/intro.js`). It used the roll the Bastion stored when the beast was acclimatised, so a DM who changed the variety afterwards (Temperament dialog) got a reveal that described Bloodcrest followed by a page that showed Ironcrown. It now reads the variety the beast's profile holds (the same one the page shows, found the same loose way), whenever the panel is drawn. The die still shows the medallion's place in this run's shuffled order. The personality cards (`M.personalityCards`) show the Bastion's stored number on the die only while the line is still the line that number gave (compared ignoring capitals and spaces); a line the DM changed, cleared or wrote in their own words shows a star (the same rule already applied to a line the DM wrote before the roll, so the screen and the tests' `lines` option now agree). The d12's note follows the same rule.
2. **A handler named `Constructor` or `__proto__` keeps its pairing** (`tools/beasthandler/bastion-link.js` `R.cleanBeast`): a `Set` replaces the plain-object duplicate check. The other lookups in the Beast Handler and Bastion code that I read are keyed by values the code makes or checks (creature ids are screened by `P.safeKey` before they reach the snapshot, receipt ids must match the message id pattern, tables are looked up by kind). An older test that expected such a handler to be dropped now expects it to be kept.
3. **Restoring an old Beast Handler backup** (`shared/js/backup-rules.js`): the Beast Handler has no Import button, so the message no longer says "use Import". It says there is nothing in the file to load, that it can be ignored, and that the beasts live in the Bastion (restore a whole-suite backup or a campaign file). Other tools' messages are unchanged.
4. **Subspecies names never break in the middle of a word** (`tools/beasthandler/beasthandler.css`): below 720 px the medallion stacks (badge above the name, name across the whole width), the name has no break-anywhere and no hyphens, and its size steps down with the medallion's own width (container units; there is a plain fallback for a browser that does not know them). Three columns from 560 px (was 480). The size is 12 px from about 360 px up and 10.3 px at 320 px.
5. **Each first-meeting panel starts at its top** (`intro.js`): smooth scrolling, or at once under reduced motion.
6. **A housed beast with no development record and no handler** now shows the "Not acclimatised yet" chip, like the same beast with a handler (`view.js`).
7. **The Bastion's three calls to the first-meeting sweep are tested** (new `tests/e2e/beasthandler-sweep.test.js`; see Tests). One small code change came with it: the sweep when the report box is closed, and at each day, now waits while the version 4 report is still unread (before, only the call at opening did), so closing the box with Esc cannot make the Bastion change a beast under a report that has not been read.
8. **Painted portraits** (`beasthandler-meet.test.js`): every picture in the art map is in the folder, loads (width and height above 0) and is shown for its variety on the Bond page; a variety with no painting shows the empty frame, no broken image and no "couldn't be loaded" note; the art map names only real varieties.
9. **The old request queue** (`tsi.beasthandler.queue`): the test now seeds the key, shows it is in Back up everything, opens the Beast Handler (and separately the Bastion), and shows it deleted and gone from Back up everything.
10. **A refused or skipped Explorer change while days pass** (`tools/bastion/tool.js`, `rules.js`): `R.applyInbox` now writes a word line for every refusal (standing change, parcel pickup, Great Rite) and every skip, into the day being passed. The day-pass loop uses `tellProblems`, which raises the warning notice for refusals and the notice for skips (not for what was applied, which is still only in the word), each under its own id (`…-1`, `…-2`) so one never replaces another. `R.settledNotices(res, { problemsOnly, suffix })` is the rule behind it.
11. **A skipped message of a kind this version does not know** (`rules.js`): the receipt now records `type: 'newer'`, and `R.bridgeChange` says "Skipped: A message of a kind this version doesn't understand", with the plain reason and no Honour/Respect instruction. Receipts saved before this change keep their old wording (nothing in them says what the message was).
12. **Guide**: the Warehouse paragraph no longer mentions the Events button or Roll Bastion Event, and its Changes from the Explorer line says Management (with Show all). The remaining mentions of Bastion Events are in `docs/BASTION-EXPLORER-REFERENCE.md`, `docs/BASTION-OVERHAUL.md` and old entries of `docs/KNOWN_ISSUES.md`, which the documentation steps (S20, S21) own; the Shrines' "no Bastion event damages a facility" sentence is still true and goes with S11.

## Decisions I made without asking

- **A cleared variety, or one the DM typed in their own words, leaves the subspecies roll out.** The review's direction said to fall back to the stored roll when the profile's variety is blank or unknown. That would bring back the reported symptom ("the marker lands on Bloodcrest, then the page says Subspecies not known yet"), so instead the reveal has nothing true to land on: the subspecies panel is left out, panel 1 says "One quick roll", the dots say "Step 1 of 2", and the page that follows shows what the Bastion holds. The stored roll is used only when a snapshot says nothing at all about the profile (not something this suite sends). If you would rather have the old fallback, it is one line in `M.revealTarget`.
- **If the variety changes while the player is looking at the landed panel**, the panel shows the new one (the page is about to show it); if it is cleared, the meeting moves on to the personality panel.
- The refusal word lines are worded "From the Explorer: a change (T4, Day 3) couldn't be used, so nothing changed: <reason>" and likewise for a parcel pickup and a Great Rite handover; a skip's word line is the same sentence its notice uses.
- A word line can only be written while a day is being passed (that is how `R.addWord` has always worked); the idle path keeps its notice only.
