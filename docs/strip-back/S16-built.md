# S16: the DM doc overhaul, as built

Branch `s16-dmdoc`, built from `docs/strip-back/D-dmdoc.md` (all section 7 defaults approved by Harry). Order followed: D section 5.

## What was built

- **Explorer (step 1).** `journey.expedition.endedDay` in `tools/explorer/journey.js`: set on End expedition, cleared on Start, read in `J.clean`, returned from `J.expedition`. For an expedition that ended in an older save it is read from the journey log's "Expedition N ended on Day D." line (`TSI.campaign.endedDayFromLog`), and is 0 (unknown) if the line has gone. No save-version bump.
- **`TSI.campaign.summary` (step 2).** `heroes` are now `[{ id, name, effects }]` (matched by hero id, so a rename cannot lose an effect); `partyEffects` (the party's own, and any effect that fits no hero, so none is hidden); `effects` still lists all; `rite` (the Great Rite held, `{ name, used }`); `expedition` `{ n, state: 'none' | 'active' | 'ended', startedDay, endedDay, daysRunning }` (days running = today minus the start day, never below 0; the days are real numbers that Reset Travel moves, so they can be 0 or below; the Explorer's record is now `{ v: 2, n, active, startedDay, endedDay }`, `endedDay` null when none/unknown, and an older record's 0 still means unknown); `orders.list` (up to five, next first; `orders.count` stays the total). `bastionComing` was not touched. New code lives in the `summary` function and in helpers added after the `C` object (`C.ORDERS_LISTED`, `C.endedDayFromLog`), so the merge with the `inDaysSave` / `RETIRED_FACILITIES` edits should be clean.
- **`shared/js/dmdoc-rules.js` (step 3).** Quest rules: `QUEST_KEY` (`tsi.dmdoc.quest`), `QUEST_MAX` (200,000), `cleanQuest`, `makeQuest`, `newerQuest` (merge by `at`), `cleanImportedText`, `joinQuest` (Replace / Add to the end, refuses whole when over the limit), `questFileName`, `IMPORT_MAX_BYTES`. New first size 1040 by 640, `NARROW_W` 760, `POPOUT_W/H` 1100 by 760, `popOutFeatures()`, `LAYOUT_VERSION` 2 (`toSaved` adds `v`; `fromSaved` ignores a layout without it, once).
- **`shared/js/dmdoc.js` (steps 4, 7).** Four panel builders (`partyParts`, `bastionParts`, `explorerParts`, the Quest panel). Each read-only panel is redrawn only when its own slice of the summary changes (and keeps its scroll position). The Quest panel is built once and never touched by the two-second refresh. Quest saving: about 0.4 s after typing, at once on blur, `pagehide`, `visibilitychange` (hidden) and when the DM doc closes or pops out; a small Saved / Saving… / Not saved status; a plain message in memory mode. The saved Quest text is read again only when the DM doc opens, when the window is focused again, when the tab comes back into view, when the box is clicked out of (blur), and when another window has done a Restore or Import (a `storage` event on `tsi.suite.replaced`, which `TSI.store.replace` now writes); never on the timer. A window takes any saved text that differs from the `{ text, at }` it last saved or loaded (`R.questChanged`, not the time alone, so a Restore's older copy shows), whenever there is no unsaved typing, even with the caret in the box (the caret stays, clamped to the new length); with unsaved typing it keeps the typing and says so. A copy of the typing is also kept in `localStorage` (`tsi.suite.dmdoc-quest-draft`, copied about 0.15 s after typing and written in full on `pagehide` / hidden) and put back at the next open if it is newer than the saved text. "Change a score" moved into the Explorer panel with a shorter help line and the last three requests. Pop out: one at a time (holds Web Lock `tsi.suite.lock.dmdoc` through `TSI.toolLock`; a second click, or one while the new window is starting up, shows a notice), opens landscape, still `noopener`.
- **`shared/components.css` (step 5).** Grid of four panels (thin gold border, soft glow, display-font headings, sentence-case body), hero rows with effect chips, Quest textarea filling its panel, a container query that stacks the panels in one column under about 760 px. Tiles and flat-section CSS removed.
- **`shared/js/doc-text.js` (step 6).** Plain functions: zip central-directory walk + `DecompressionStream('deflate-raw')`, XML-to-text (separate and tested), PDF text with each item's `hasEOL` and a blank line between pages (PDF.js from `shared/lib/pdfjs`, loaded only when a PDF is chosen, same condition as the Combat Tracker), .txt / .md via `FileReader`. Plain messages for a scan, an old .doc, a password, a damaged zip, over 20 MB, empty and unsupported files. "Reading…" state, `TSI.oneAtATime`. Script tag added to `index.html`, `tests/harness.html`, `tests/rules.html`. `licences/README.md` updated.
- **Guide (step 8).** `guide.html` DM doc paragraph rewritten for the four panels, the Quest box, imports, Clear asking first, one pop-out, and the Restore caveat.
- **Wording.** The Bastion's notice no longer says "The Day Log keeps it"; the Change-a-score dialog and the DM doc's help text no longer promise a Day Log. `R.applyDmEdits` still logs (left for the Bastion removal step).

## Decisions made without asking

- Expedition line placed right under Day (handover lists it last); "began today (Day N)" for a same-day start; plain hyphen in "Expedition ended - Day 4 to Day 9".
- Next word shows every line for that day, not just the first plus a count.
- Last three score changes listed in the panel (was six).
- The Quest box is not changed under a focused or unsaved box; the newer copy waits and shows after blur.
- A `.doc` is refused with its own message; `.markdown` and `.text` are accepted as text.
- Import over the limit is refused whole (never cut), and the box itself stops at 200,000 characters (`maxlength`).
