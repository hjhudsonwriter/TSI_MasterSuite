# Click-through tests

These open the suite from its files (`file://`) in a headless Chromium browser (the engine inside Edge) and click through it, at Harry's screen sizes:

- the laptop in a maximised Edge window (1707 × 930, pixel ratio 1.5) and in full screen (1707 × 1067)
- the TV (1920 × 1080, pixel ratio 1)
- a smaller window (1280 × 720)

They're for the people building the suite. Harry doesn't need to run them; his checks are the tickbox lists in each pull request, and `tests/rules.html`, which he can double-click.

`tests/archive/` holds the tests of code that was archived (since Build 3 of the Bastion overhaul, the Mercenary Brigade and the old single-roll war). Nothing loads them; each file's header says how to run it with its archived code.

## Running them

Needs Node.js and Playwright with its Chromium browser.

```
node tests/e2e/phase1.test.js
```

If Playwright is installed globally, point Node at it, e.g. `NODE_PATH=$(npm root -g) node tests/e2e/phase1.test.js`. Screenshots go to the folder in `TSI_SHOTS` (or the system temp folder).

## What the tests use

- `tests/harness.html` is a copy of `index.html` that adds a pretend **Demo tool** (`tests/fixtures/`). It tests saving, Export and Import, shutting a tool down, player windows and error handling before any real tool exists. It has its own saved data (the browser database `tsi.test`, set by `data-tsi-space="test"` on its `<html>`) and its own backups, so nothing it does can reach the real suite's saves or backups, and neither will load the other's backup files. The top bar says "Test page".
- Buttons ignore a second click within 350 ms (double-click protection), so the helpers pause briefly before clicking the same button again.
- Don't use Playwright's request interception with player windows: it stops their stylesheets loading.
- `beasthandler.test.js`: the Beast Handler companion. The Bastion is built in one window (a Roost with Elara's wyvern and a second wyvern, a Griffin Tower, no Dire Wolf Den, one DM-only Chronicle note) and the companion is opened in another. It checks the Home directory and "Viewing as", other players' beasts as plain lines, the main screen, the harmless greeting, Profile, Orders (free training only, the confirm screen with Send switched off, the whole-building lock), the read-only Chronicle, a phone-sized screen, the laptop and the TV, reduced motion, and that the Bastion itself never changed.
- `beasthandler-write.test.js`: the companion asking the Bastion, on the laptop in two windows. Rolling only suggests; Save and Send request show "waiting" and then the Bastion's answer; exactly one order and no gold; a reload or a second copy never makes a second order; a double press sends one request; the Bastion switched off holds a request until it is switched back on; a request that no longer qualifies is refused with its reason; and the Dire Wolf's portrait follows its Regional Variety.
- `beasthandler-meet.test.js`: meeting a beast for the first time (21 October 2026), on the laptop and on a phone page with the code swap. No picture or page of the beast before the end; the three panels and their buttons; the five tap choices, Roll and the warning for a name of your own; one request (the subspecies and any line written or changed), sent once; the panel fading to black, the welcome words and black again, in order and at real speed; the curtain waiting for a slow picture and giving up on one that never comes; the picture appearing at once while the Bastion's answer is awaited, marked as waiting, and the marks going when it answers; lines already written for the beast kept; a refused request bringing the meeting back with the reason and the choices put back (across a reload), without putting back a line the DM changed meanwhile; another handler's waiting request not shown; clearing the subspecies shown as waiting; a name with no painting, and a missing picture file, said so; Skip for now (laptop; on a phone only after a refusal); closing the page part-way sends nothing; keyboard use; reduced motion; the black screen removed if the tool is closed; every button at least 44 px on a phone. (A first-time request kept by an earlier version of the phone page, and a refusal with Skip, are checked on the phone.) It speeds the sequence up with `window.TSI_BH_SPEED`.
- `beasthandler-phone.test.js` (set `TSI_PHONE_URL=http://127.0.0.1:8123/TSI_MasterSuite/beasthandler.html` to run the phone's half against the page served from a web address, as on GitHub Pages; serve the folder above the repo with `python3 -m http.server 8123 --bind 127.0.0.1`): the phone page (`beasthandler.html`) in its own phone-sized window against the DM's Bastion. The page loads no DM tool; a pairing code links it, a wrong one doesn't; a snapshot code shows the beasts and one for another handler or a changed one is refused; a request code is applied once by the Bastion (pasting it again changes nothing) and the answer comes back in a new snapshot; forged, truncated, changed and rubbish codes leave no receipt; a taken-back code stops working; an older snapshot pasted later is refused; a request that was never sent can be forgotten; a damaged stored snapshot is forgotten instead of blanking the page; a request queued on the laptop is answered once and taken out of the queue by the Bastion; and the page has no sideways scroll and no button under 44 px at 390 px wide, the bond pills' names show whole and the bond headline doesn't break inside a word at 390, 360 and 320 px, the picture is a proper size held sideways, a control reached by keyboard isn't left under a bar, and the code boxes are 16 px (so iPhone Safari doesn't zoom in).
